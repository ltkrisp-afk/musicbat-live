## Required launch sequence
1. **Prepare a production-v16-specific release in non-production.** Preserve Retrofutura, existing resources, original track IDs/assets and financial history. Use the verified v20 security/player as the code baseline. Reconcile migration identity divergence; do not deploy current Stage 4 migrations unchanged. Rehearse upgrade, partial failure, preserving rollback and restore against a production-shaped fixture; no guessed ownership.
2. **Resolve production delivery services before activation.** The D1 Radio adapter is intentionally test-only. With live Stripe mode it is not selected: an authorized existing regular Radio service/runtime and reviewed original recording/composition permissions must be established, or a separately reviewed minimal adaptation must be proven in non-production. Do not set test flags in production or re-enable raw audio URLs. The recovery runner is also explicitly sandbox-only and cannot be advertised as live recovery.
3. **Finish operational readiness.** Establish current D1/R2 restore evidence, non-destructive rollback compatible with post-migration purchases, monitored webhook/recovery/Radio errors and named response owner. Replace obsolete v13 operational instructions with an exact v16 release profile. Approve and publish contact, terms/privacy, delivery/refund/withdrawal and rights/abuse policies before accepting public sales.
4. **Qualify the actual one-artist catalog and mobile path.** Owner supplies/reviews recording and composition authority and any collaborator/cover permissions; retain rights evidence, territories, expiry, classification, prices and audio fingerprints. Do not transplant generated-tone grants. Physical Safari testing is still required; existing purchased test audio can be reused without a new transaction.
5. **Owner-controlled business gate.** Entity, banking, merchant verification and commercial activation stay on hold. Once authorized, verify live merchant/connected artist readiness, allowed payment-method fee schedule, correct endpoint signing secret and account/mode identity using read-only provider checks before unpausing commerce.
6. **Only after explicit production approval:** take a current restore point; pause writes in a verified manner, apply the rehearsed release to the existing production project, inspect native deployment and migration effects, verify actual hosted Radio, account isolation and download delivery. Preserve webhook retry handling during maintenance. A real charge/refund is a separate authorization; this audit makes none. Re-evaluate GO before opening sales.
